## Root cause

The API container was redeployed 55 minutes ago to version 2.3.2, which introduced a code change in order validation that calls .strip() on a None value, causing every POST /api/orders to return a 500 error.

Confidence: high. Evidence:
- list_containers shows api container Up 55 minutes, matching the deploy time
- get_logs api shows repeated 'NoneType' object has no attribute 'strip' errors starting at 21:41:17
- recent_changes logs deployment of api 2.3.2 with 'refactor order validation' 55 minutes ago
- Web search confirms AttributeError when calling .strip() on None

## Fix

**Rollback API to previous version**

1. `rollback(container=api, to_image=shopapp/api:2.3.1)`

How to undo: Rollback api to shopapp/api:2.3.2 or redeploy version 2.3.2

What was done:
- rolled back api to shopapp/api:2.3.1

Options that were offered:
- Rollback API to previous version (recommended) (approved)

## Follow-ups

- Risk of the chosen fix: Temporarily loses the refactor changes from version 2.3.2
- Risk of the chosen fix: Requires a follow-up deploy of a corrected version
- Long-term fix suggested by the investigator: Update the API code to guard against `None` values before calling `.strip()` (e.g., `if value: value.strip()`) or ensure the required field/config is present, then redeploy the corrected version.
