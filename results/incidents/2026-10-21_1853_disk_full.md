## Root cause

A nightly database backup job added on 2026-10-19 creates ~15.8GB dump files in /var/lib/postgresql/backups, filling the 50GB PostgreSQL volume to 100% and causing PostgreSQL write failures ("could not extend file") that surface as order placement errors.

Confidence: high. Evidence:
- check_disk shows /var/lib/postgresql at 100% used (50GB/50GB)
- check_folder_sizes shows two 15.8GB dump files in /var/lib/postgresql/backups
- db container logs contain repeated "ERROR: could not extend file ... No space left on device"
- recent_changes records addition of nightly backup job on 2026-10-19

## Fix

**Move oldest backup, restart DB, disable backup job**

1. `move_files(from_path=/var/lib/postgresql/backups/shop_2026-10-20.dump, to_mount=/)`
2. `restart(container=db)`
3. `disable_job(job=db-backup)`

How to undo: Re-enable the backup job (cron) and move the backup file back if needed.

What was done:
- moved /var/lib/postgresql/backups/shop_2026-10-20.dump (15.8 GB) to /moved-files/ on /
- restarted db
- turned off the job db-backup

Options that were offered:
- Move oldest backup, restart DB, disable backup job (recommended) (approved)
- Move oldest backup, restart DB, keep backup job
- Move newest backup, restart DB, disable backup job
