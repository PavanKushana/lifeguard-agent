## Root cause

The API container version 2.3.2 was deployed with incorrect database credentials (likely missing or wrong DB_PASSWORD), causing password authentication failures against PostgreSQL and resulting in 500/503 errors for API requests.

Confidence: high. Evidence:
- API logs show first authentication error at 2026-10-22 21:38:15, right after deployment of api 2.3.2 at 21:37:15 (recent_changes)
- Database logs confirm repeated FATAL password authentication failures for user 'shop' starting at the same timestamp (get_logs db)
- Health endpoint returns HTTP 503 due to database connection failure (check_endpoint)
- No memory or disk pressure exists (get_metrics, check_disk)

## Fix

**Rollback API to previous version 2.3.1**

1. `rollback(container=api, to_image=shopapp/api:2.3.1)`

How to undo: Rollback api container back to shopapp/api:2.3.2
