## Root cause

The API container crashes on startup because the newly deployed image 2.3.2 imports `pydantic_settings` which is not installed, causing a restart loop that leaves nginx without a healthy backend and results in 502 Bad Gateway responses.

Confidence: high. Evidence:
- list_containers shows the API container has restarted 14 times and is currently Restarting
- get_logs for the API container repeats ModuleNotFoundError: No module named 'pydantic_settings' at each start attempt
- recent_changes records a deployment of API 2.3.2 21 minutes ago with note 'settings moved to pydantic-settings'
- check_endpoint returns HTTP 502 for the shop front page

## Fix

**Rollback API to previous version 2.3.1**

1. `rollback(container=api, to_image=shopapp/api:2.3.1)`

How to undo: Redeploy API 2.3.2 after adding the missing pydantic-settings dependency to the image

What was done:
- rolled back api to shopapp/api:2.3.1

Options that were offered:
- Rollback API to previous version 2.3.1 (recommended) (approved)

## Follow-ups

- Risk of the chosen fix: The new feature (settings moved to pydantic-settings) is lost until the image is fixed and redeployed
- Long-term fix suggested by the investigator: Update the CI/CD pipeline to install all Python dependencies (including `pydantic-settings`) before building the API image, and add a health‑check or pre‑deploy test that imports the module to catch missing packages early.
