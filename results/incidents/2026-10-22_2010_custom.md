## Root cause

The scheduled job 'collect-debug-logs' runs every 10 minutes and writes debug logs to /var/log on the root filesystem, which has filled the root partition to 97% usage (0.9 GB free). This causes the api container to fail with 'No space left on device' when attempting to write log entries, resulting in 500 errors on dynamic requests.

Confidence: high. Evidence:
- check_disk: root filesystem / has 0.9 GB free of 30 GB (97% used)
- get_logs api: repeated errors 'failed to write log entry: No space left on device' starting 2026-10-22 19:55:41
- check_folder_sizes /var: /var/log consumes 17.9 GB
- Scheduled jobs: collect-debug-logs runs every 10 minutes and is on

## Fix

**Disable debug log job and move logs to free space**

1. `disable_job(job=collect-debug-logs)`
2. `move_files(from_path=/var/log, to_mount=/var/lib/postgresql)`
3. `restart(container=api)`

How to undo: Move files back from /var/lib/postgresql/log to /var/log and re-enable collect-debug-logs job

What was done:
- turned off the job collect-debug-logs
- moved /var/log (17.9 GB) to /var/lib/postgresql/moved-files/ on /var/lib/postgresql
- restarted api

Options that were offered:
- Disable debug log job and move logs to free space (recommended) (approved)
- Disable debug log job and move docker data to free space
- Disable debug log job only (temporary relief)
