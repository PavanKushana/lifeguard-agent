## Root cause

The collect-debug-logs cron job (added 2026-10-20) writes large debug dumps to /var/log/shop/debug.log, filling the root filesystem (97% used, 0.9GB free) and causing the API container to fail with ENOSPC when writing logs, resulting in 500 errors for dynamic requests.

Confidence: high. Evidence:
- API logs show repeated 'ERROR ... failed to write log entry: No space left on device' starting 2026-10-22 20:05:39
- Root disk / is 97% used (0.9GB free of 30GB) per check_disk
- /var/log/shop/debug.log consumes 17.5GB per check_folder_sizes
- Recent changes show collect-debug-logs cron job added 2026-10-20 20:20:39

## Fix

**Disable cron job, move debug.log to larger disk, restart API**

1. `disable_job(job=collect-debug-logs)`
2. `move_files(from_path=/var/log/shop/debug.log, to_mount=/var/lib/postgresql)`
3. `restart(container=api)`

How to undo: Re-enable collect-debug-logs cron job manually; move /var/lib/postgresql/debug.log back to /var/log/shop/debug.log if needed; restart api

What was done:
- turned off the job collect-debug-logs
- moved /var/log/shop/debug.log (17.5 GB) to /var/lib/postgresql/moved-files/ on /var/lib/postgresql
- restarted api

Options that were offered:
- Disable cron job, move debug.log to larger disk, restart API (recommended) (approved)
- Disable cron job and move debug.log (no API restart)
- Move debug.log to larger disk, keep cron job running
