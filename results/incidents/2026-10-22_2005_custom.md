## Summary

Users reported: "Product pages load slowly or show 'Service unavailable' errors; the cache container has restarted several times in the last half hour." Root cause: The API version 2.3.2 introduced a Lua script for atomic cart updates that triggers a segmentation fault in Redis 7.4 (lua_call_function → lua_pcall → lua_resume → lua_yield), causing the cache container to crash repeatedly and leading to 500 errors and slow product pages. Fix applied: Rollback API to 2.3.1. Result after checking the server: FIXED.

## Root cause

The API version 2.3.2 introduced a Lua script for atomic cart updates that triggers a segmentation fault in Redis 7.4 (lua_call_function → lua_pcall → lua_resume → lua_yield), causing the cache container to crash repeatedly and leading to 500 errors and slow product pages.

Confidence: high. Evidence:
- Cache logs show three segfaults at 19:37:36, 19:49:36, 20:01:36 with stack trace pointing to Lua functions
- API deployed to 2.3.2 at 19:35:36 with note 'atomic cart updates with Lua script'
- API logs show 500 errors 'connection to cache:6379 refused' immediately after each cache crash
- Memory and disk usage are well within limits (cache memory 45/256 MiB, disks 37% used)
