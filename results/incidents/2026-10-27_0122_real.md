## Root cause

The API container was upgraded to version 2.3.2, which requires the environment variable SHOP_DB_PASSWORD, but this variable is not set, causing the container to crash on start and return HTTP 502.

Confidence: high. Evidence:
- API container shows 9 restarts and logs repeatedly contain 'FATAL config error: SHOP_DB_PASSWORD is not set (new in 2.3.2)'
- Recent changes show deployment of api 2.3.2 at 2026-10-27 01:22:02, just before the restart loop began

## Fix

**Rollback API to 2.3.1**

1. `rollback(container=api, to_image=lifeguard/real-api:2.3.1)`

How to undo: Redeploy api 2.3.2 after manually setting the SHOP_DB_PASSWORD environment variable

What was done:
- rolled back api to lifeguard/real-api:2.3.1
