## Root cause

The nightly database backup job added on 2026-10-19 writes large dump files to /var/lib/postgresql/backups, filling the PostgreSQL data disk to 100% and preventing PostgreSQL from extending its data files, causing 500 errors on order creation.

Confidence: high. Evidence:
- Disk check shows /var/lib/postgresql at 100% used (50G/50G) while root filesystem has 18.8G free
- Folder size reveals two backup dumps consuming 31.6G inside /var/lib/postgresql/backups
- Recent changes log indicates a nightly database backup job was added on 2026-10-19
- PostgreSQL logs repeatedly show 'could not extend file ... No space left on device' errors coinciding with failed order POSTs

## Fix

**Move oldest backup and disable backup job**

1. `move_files(from_path=/var/lib/postgresql/backups/shop_2026-10-20.dump, to_mount=/)`
2. `disable_job(job=db-backup)`

How to undo: Re-enable the db-backup job via the scheduler (manual); the moved backup file can be moved back if needed

What was done:
- moved /var/lib/postgresql/backups/shop_2026-10-20.dump (15.8 GB) to /moved-files/ on /
- turned off the job db-backup

Options that were offered:
- Move oldest backup and disable backup job (recommended) (approved)
- Move oldest backup and keep backup job (manual cleanup required)
