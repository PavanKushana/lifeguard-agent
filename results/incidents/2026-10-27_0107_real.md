## Root cause

The API container (lifeguard/real-api:2.3.2) crashes on start because it requires the environment variable SHOP_DB_PASSWORD, which is not set in the container's environment.

Confidence: high. Evidence:
- list_containers shows api container in Restarting state with 10 restarts
- get_logs for api repeats 'FATAL config error: SHOP_DB_PASSWORD is not set (new in 2.3.2)'
- recent_changes records deploy of api 2.3.2 at 2026-10-27 01:06:38, just before first crash
- recent_changes shows no prior setting of SHOP_DB_PASSWORD for the api container

## Fix

**Rollback api to version 2.3.1**

1. `rollback(container=api, to_image=lifeguard/real-api:2.3.1)`

How to undo: Rollback api to lifeguard/real-api:2.3.2 after manually setting SHOP_DB_PASSWORD in the container environment

What was done:
