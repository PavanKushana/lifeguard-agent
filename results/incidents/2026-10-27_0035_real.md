## Root cause

The api container was upgraded to version 2.3.2 which requires the SHOP_DB_PASSWORD environment variable, but that variable is not set, causing fatal config errors on startup and continuous restarts, leading to HTTP 502 on /api/health.

Confidence: high. Evidence:
- check_endpoint returned HTTP 502
- list_containers shows api container with 15 restarts and status Restarting
- get_logs for api shows repeated "FATAL config error: SHOP_DB_PASSWORD is not set (new in 2.3.2)"
- recent_changes shows deploy at 2026-10-27 00:30:00 upgrading api from 2.3.1 to 2.3.2

## Fix

**Rollback api to 2.3.1**

1. `rollback(container=api, to_image=lifeguard/real-api:2.3.1)`

How to undo: Rollback api to 2.3.2 again (if env var is set later)

What was done:
- rolled back api to lifeguard/real-api:2.3.1
