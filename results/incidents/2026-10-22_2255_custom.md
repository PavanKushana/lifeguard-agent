## Root cause

The recent deployment of API version 2.3.2 introduced a heavy analytics query that exceeded the PostgreSQL container's 1024 MiB memory limit, causing an OOM kill (signal 9) that corrupted the database control files (global/pg_control) and prevented the DB from restarting.

Confidence: high. Evidence:
- db container exited with code 137 (OOM) 50 minutes ago (list_containers)
- DB logs show server process killed by signal 9 while running a heavy analytics query, then fatal error opening global/pg_control (get_logs)
- Metrics show DB memory limit 1024 MiB, usage 0 MiB after crash (get_metrics)
- Recent changes show API deployed to 2.3.2 (new analytics dashboard) 1 hour before crash (recent_changes)

## Fix

**Rollback API to 2.3.1 and restart DB**

1. `rollback(container=api, to_image=shopapp/api:2.3.1)`
2. `restart(container=db)`

How to undo: Rollback api container back to shopapp/api:2.3.2

What was done:
- rolled back api to shopapp/api:2.3.1
- restarted db

Options that were offered:
- Rollback API to 2.3.1 and restart DB (recommended) (approved)
- Increase DB memory limit to 2048 MB and restart DB
- Restart DB only
