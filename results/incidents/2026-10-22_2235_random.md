## Root cause

The Redis 7.5 security update deployed at 2026-10-22 22:06:03 introduced an unknown directive 'maxmemory-policy' in /etc/redis/redis.conf line 17, causing the cache container to fatally error on startup and enter a restart loop. This makes the API unable to connect to Redis, resulting in 503 errors on product searches and health checks.

Confidence: high. Evidence:
- list_containers shows cache container with 6 restarts and status 'Restarting'
- get_logs cache repeats 'FATAL CONFIG FILE ERROR Unknown directive maxmemory-policy at line 17' starting 2026-10-22 22:07:03
- recent_changes records 'Deployed cache redis:7.5 (security update)' at 2026-10-22 22:06:03
- get_logs api shows 'Redis connection failed: Connection refused' errors from 2026-10-22 22:08:03 onward and check_endpoint returns HTTP 503

## Follow-ups

- Risk of the chosen fix: Loses Redis 7.5 security update; will need re-application after config validation
- Long-term fix suggested by the investigator: Ensure configuration changes are validated before deployment (e.g., test the Redis config with `redis-server /etc/redis/redis.conf --verbose` or use a config linter) and keep version‑controlled config files so that erroneous directives are caught in CI/CD rather than pushed to production.
