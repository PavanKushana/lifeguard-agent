## Root cause

The API container's memory limit was reduced from 512 MB to 16 MB, causing the Linux OOM killer to terminate the process (exit code 137) immediately after startup, resulting in continuous restarts and HTTP 502 errors.

Confidence: high. Evidence:
- list_containers shows API container restarting with status "Restarting (137)"
- get_metrics shows API memory limit 16 MiB, usage 0 MiB
- recent_changes shows API memory limit changed from 512 MB to 16 MB 35 seconds ago
- get_logs shows API starts listening on :8000 then exits with no further output

## Fix

**Restore API memory limit to 512 MB and restart container**

1. `set_memory_limit(container=api, memory_mb=512)`
2. `restart(container=api)`

How to undo: Set API memory limit back to 16 MB (not recommended)

What was done:
- set the memory limit of api to 512 MB
- restarted api

Options that were offered:
- Restore API memory limit to 512 MB and restart container (recommended) (approved)
- Increase API memory limit to 1024 MB and restart container

## Follow-ups

- Risk of the chosen fix: Uses more memory than the 16 MB limit, but still far under total available
- Long-term fix suggested by the investigator: Set memory limits based on actual observed usage (e.g., monitor with `docker stats` or Prometheus) and keep a safety margin; avoid arbitrary low limits that cause OOM kills.
