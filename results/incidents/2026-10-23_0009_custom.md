## Summary

Users reported: "The shop homepage loads but product searches fail with 'Service unavailable', and the API health check returns 503." Root cause: The cache container was upgraded from redis:7.4 to redis:7.5, but the mounted configuration file /etc/redis/redis.conf still contains the directive 'maxmemory-policy' which is unknown in Redis 7.5, causing the Redis server to fail on startup and enter a restart loop. ## Root cause

The cache container was upgraded from redis:7.4 to redis:7.5, but the mounted configuration file /etc/redis/redis.conf still contains the directive 'maxmemory-policy' which is unknown in Redis 7.5, causing the Redis server to fail on startup and enter a restart loop.

Confidence: high. Evidence:
- cache logs show 'Unknown directive maxmemory-policy at line 17' immediately after the 2026-10-22 23:39:07 deploy of redis:7.5
- cache container status is Restarting with 6 restarts, last 2 minutes ago
- api logs show Redis connection refused errors starting at 2026-10-22 23:41:07, leading to 503 responses
- recent_changes confirms only the cache image changed 30 minutes ago

## Fix

**Rollback cache to redis:7.4**

1. `rollback(container=cache, to_image=redis:7.4)`

How to undo: rollback cache to redis:7.5 after providing a valid redis.conf

## Follow-ups

- Risk of the chosen fix: Loses the security update from redis:7.5 until config is fixed and re-upgraded
- Long-term fix suggested by the investigator: Update the Redis configuration file to be compatible with Redis 7.5 (e.g., ensure `maxmemory-policy` is a valid directive or remove it if unnecessary) before deploying the new image, or pin the cache service to a specific stable version until the config is validated.
